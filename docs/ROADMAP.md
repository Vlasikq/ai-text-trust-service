# Roadmap

Документ фиксирует ограничения, которые приняты в текущем MVP сознательно, и приоритеты дальнейшей работы. Каждый пункт в «Известных ограничениях» сопровождается ссылкой на место в коде, где ограничение проявляется, и объяснением, почему в MVP сделано именно так.

## Принципы приоритизации

1. Безопасность важнее удобства, удобство важнее производительности. Уязвимости первого приоритета закрываем раньше фич.
2. Не делаем впрок. Если ограничение не мешает реальным пользователям сегодня, оптимизировать заранее не будем.
3. Один PR — одна логически целая правка. Mega-PR не принимаем.

## Известные ограничения

### Безопасность

**L1. Refresh-токен в `localStorage`**

- Где: [apps/web/src/lib/api.ts:12](../apps/web/src/lib/api.ts#L12).
- В чём проблема: XSS-инъекция читает токен из `localStorage`.
- Что закрываем сейчас: ротация и детект повторного использования в `/auth/refresh` сужают окно эксплуатации, плюс CSP в Next.js ограничивает источники скриптов.
- План: перевести refresh на httpOnly-куку с `SameSite=Strict`. Отдельный BFF не нужен, потому что Caddy уже даёт same-origin: достаточно расширить `/auth/refresh` на чтение токена из куки. Затрагивает фронт и один endpoint.

**L2. JWT-библиотека (закрыто): миграция с `python-jose` на `pyjwt`**

- Что было: `python-jose` с уязвимостями CVE-2024-33663 (algorithm confusion) и CVE-2024-33664 (jwks DoS), последний релиз 2022 года.
- Что стало: `pyjwt[crypto]` версии 2.12.1, активно поддерживается. См. [src/app/auth/tokens.py:13](../src/app/auth/tokens.py#L13). 47 auth-тестов после миграции остались зелёными.

**L3. `JWT_SECRET` в открытом виде в docker-compose**

- Где: [scripts/deploy/docker-compose.prod.yml:25](../scripts/deploy/docker-compose.prod.yml#L25).
- Что закрываем сейчас: публичного SSH на виртуалке в проде нет, debug-ключ в cloud-init убирается после защиты ВКР.
- План: YC Lockbox и получение секрета через `yc lockbox payload get` в bootstrap или из sidecar-контейнера.

**L4. Контейнер `artifact-sync` работает от root**

- Где: [scripts/deploy/docker-compose.prod.yml:71](../scripts/deploy/docker-compose.prod.yml#L71).
- В чём причина: именованный volume по умолчанию принадлежит `root:root`, и `appuser` с uid 1000 не может создавать в нём папки.
- Что закрываем сейчас: контейнер живёт около минуты, у него нет shell и нет открытых портов.
- План: init-контейнер, который один раз меняет владельца тома на `1000:1000`, после чего `artifact-sync` запускается от `appuser`. Приоритет низкий — текущая схема безопасна.

**L5. Container Registry открыт на чтение**

- Где: настройка YC IAM `system:allUsers / images.puller`.
- В чём причина: cloud-init проще без `docker login`.
- Что не утекает: секреты лежат в env, а не в образе; пароли от prod-БД и API-ключи в Registry не попадают.
- План: при коммерциализации — приватный Registry плюс учётные данные сервисного аккаунта в Lockbox.

### Производительность и масштабирование

**P1. Rate-limiter живёт в памяти процесса**

- Где: [src/app/middleware/ratelimit.py:42](../src/app/middleware/ratelimit.py#L42).
- В чём проблема: при `--scale api=N` каждый процесс считает счётчики у себя, и фактический предел становится равен `N × значение из конфига`.
- Что закрываем сейчас: один контейнер с одним процессом, и в этой конфигурации лимиты корректны.
- План: переключить `Limiter(storage_uri="redis://...")`, когда появится больше одного API-процесса. Это добавит Redis в стек.

**P2. Одна виртуалка, без HA**

- Где: всё описано в одном файле `scripts/deploy/docker-compose.prod.yml`.
- Что есть: managed Postgres приходит с HA из коробки. У API и фронта такой защиты нет — они единая точка отказа.
- План: вторая виртуалка, YC Application Load Balancer и общее хранилище для трансформера (S3FS или NFS). Цена решения: усложнение деплоя и дополнительный биллинг за ALB.

**P3. Async-режим во фронте пока не подключён**

- Где: [apps/web/src/components/AnalyzeForm.tsx](../apps/web/src/components/AnalyzeForm.tsx) ходит синхронно в `/api/v1/analyze`.
- В чём проблема: при `DETECTOR_TYPE=cascade` в серой зоне на CPU ответ идёт 5–15 секунд, и UI всё это время заблокирован.
- Что закрываем сейчас: TF-IDF резолвит около 92% запросов меньше чем за 100 мс. По таймауту 3 секунды клиент получает 200 с предупреждением `inference_timeout` и понятную ошибку.
- План: добавить флаг «долгий анализ» в UI, и в этом случае ходить через `/api/v1/jobs` с поллингом. На бэке всё уже готово.

**P4. Холодный старт около 60 секунд**

- Где: lifespan, alembic, прогрев.
- Главный вклад вносит загрузка трансформера на 1.4 ГБ с диска; mmap здесь невозможен из-за volume.
- План: либо подготовить трансформер в memory-mapped-формат на этапе сборки образа, либо отделить воркер (каскад) от API (только TF-IDF) — тогда API стартует меньше чем за 5 секунд.

**P5. Кеш только в памяти процесса**

- Где: [src/app/cache.py:19](../src/app/cache.py#L19) — `OrderedDict`.
- В чём проблема: при нескольких процессах кеш не шарится, при рестарте контейнера теряется.
- Что закрываем сейчас: `cache.hit_rate` из `/ready` показывает реальную пользу кеша. Если он низкий, мигрировать незачем.
- План: вынести в общий Redis, когда hit-rate перевалит за 30% и будет больше одного процесса.

### Качество и наблюдаемость

**Q1. Калибратор Платта не загружен в проде**

- Где: папка `artifacts/calibration/` пустая, после lifespan `app.state.calibrator = None`.
- Что это значит: сервис работает на сырых вероятностях детектора. Они могут плохо отражать реальность — модель сообщает уверенность 0.95, а попадает в 70%.
- План:
  1. Запустить `make calibration` (нужно добавить такой Makefile-таргет; пока есть только скрипт `scripts/calibration_eval.py`).
  2. Сохранить артефакты в `artifacts/service/calibration/`.
  3. Дополнить `scripts/export_service_artifacts.py` включением калибровки.
  4. Передеплоить — lifespan подхватит калибратор автоматически.

**Q2. Prometheus scrape в проде не настроен**

- Где: `/metrics` отдаётся, но никто его не читает.
- План: либо YC Monitoring через нативную интеграцию, либо Grafana Cloud со scrape-агентом. Минимальные дашборды: латентность по перцентилям 50/95/99, запросов в минуту с разбивкой по вердикту, доли путей каскада, насыщение БД.

**Q3. Нет алертов на model drift**

- Где: метрики `aitrust_confidence` копятся как histogram, но тренд никто не отслеживает.
- Сценарий: появляется новый AI-генератор, распределение уверенностей сдвигается, нужно переобучение.
- План: cron-задача раз в неделю считает KS-статистику между последней неделей и базовой выборкой; если `p < 0.01`, отправляется алерт. Запускать удобно в YC Cloud Functions.

**Q4. Нет детекта дрейфа во входных данных**

- В чём проблема: пользователи могут систематически слать тексты из домена, на котором модель не училась, и качество тихо просядет.
- План: писать в БД характеристики входных текстов (длина, лексическое разнообразие, домен), а еженедельный скрипт будет сравнивать их с распределением обучающей выборки.

### Качество кода

**C1. Нет тестов на `worker.py`**

- Где: [src/app/worker.py](../src/app/worker.py) — 329 строк, тестов нет.
- Что это значит: обработка async-задач покрывается только косвенно через batch e2e.
- План: в рамках фазы 5 санации написать `tests/unit/test_worker.py` с моками детектора. Сценарии: основной путь, ошибка, статус `NO_DECISION`, гонка на `claim_next`, корректное завершение.

**C2. У фронта нет unit-тестов**

- Где: в `apps/web/` нет `jest.config.*` и `vitest.config.*`.
- План: Vitest и `@testing-library/react`. Минимум три теста: `AnalyzeForm` на валидацию, `AuthForm` на login-flow, `ResultCard` на рендер разных уровней риска.

**C3. Runtime-код импортирует из `scripts/`**

- Где: [src/app/explanation/markers.py:15](../src/app/explanation/markers.py#L15), [src/app/preprocessing/pipeline.py:12](../src/app/preprocessing/pipeline.py#L12).
- В чём проблема: продакшн-код зависит от `scripts/`, которые формально живут как training-инструменты. Из-за этого `pyproject.toml` собирает `scripts/` в wheel, а тесты делают `sys.path.insert`.
- План: в рамках фазы 3 санации перенести `text_cleaning.py` и `stylometric_features.py` в `src/app/`. Артефакты при этом не сломаются — проверено, в pickle нет ссылок на `scripts.*`.

**C4. `schemas.py` — монолит на 361 строку**

- Где: [src/app/schemas.py](../src/app/schemas.py).
- В чём проблема: в одном файле живут шесть разных доменов: analyze, auth, jobs, batch, explanation и общий слой.
- План: фаза 7 санации (опциональная) разбивает файл на `src/app/schemas/{common,analyze,auth,jobs,batch,explanation}.py` с реэкспортом через `__init__.py`. Не критично, чистая эстетика.

## Что в roadmap не входит

Закрепляем явно, чтобы задачи не расползались.

| Не делаем | Почему |
|---|---|
| Нативное приложение для iOS | Installable web app (manifest + standalone-окно) покрывает базовый мобильный сценарий. Полноценный PWA с service worker и офлайном сознательно не делали — целесообразность не нашлась. |
| OAuth/OIDC через внешнего провайдера (Google, Яндекс) | Один пользователь — один аккаунт, SSO не требуется. Внешний провайдер добавит сетевой переход на каждый логин и новую зависимость. |
| GraphQL | REST с типизированным OpenAPI закрывает все сценарии. GraphQL принёс бы свой стек кеширования и авторизацию на уровне резолверов. |
| Микросервисы | Один сервис, один деплой, один процесс анализа. Разделение на детекторы, auth и batch — преждевременная оптимизация. |
| Web-сокеты под async-задачи | Поллинг `/api/v1/jobs/{id}` раз в 2 секунды покрывает 99% случаев. WebSocket добавляет состояние и проблемы переподключения. |
| Multi-tenancy | MVP однотенантный. Превратить `users` в `orgs → tenants` — нетривиальный рефакторинг; делаем по коммерческому запросу. |

## Метрики готовности к V1 (после защиты ВКР)

Это следующая зрелая точка перед коммерческим релизом. Чтобы её достичь, нужно закрыть:

- [ ] L1 и L3 — обязательный security-минимум (L2 уже закрыт: `pyjwt` вместо `python-jose`);
- [ ] P3 — асинхронный UX во фронте;
- [ ] Q1 — калибратор в проде;
- [ ] Q2 — Prometheus и хотя бы один дашборд;
- [ ] C1 и C2 — тесты воркера и фронта;
- [ ] C3 — чистая структура импортов.

Остальные пункты (L4–L5, P1–P2, P4–P5, Q3–Q4, C4) — по запросу пользователей или операционной необходимости.
